Пользователь вызвал `/routine-miner`. Действуй по скиллу `routine-miner` из
плагина `routine-miner`. Майнер живёт в ctxdb и запускается только через CLI:

```
node "C:\Users\er-ka\Documents\z-code\ctxdb\src\cli.mjs" routines <подкоманда>
```

1. Определи режим по тексту после команды:
   - пусто или `статус`/`status` — `routines status`: сколько рутин, авто/ручных,
     суммарные повторы и топ по частоте;
   - `скан`/`scan` — `routines scan`: запусти майнер, дождись конца и перескажи
     итог — сколько кластеров найдено, какие скиллы созданы или обновлены;
   - `проверить <текст>`/`test <текст>` — `routines test "<текст>"`: покажи,
     какая рутина распознана, её score, `uses` и путь к `SKILL.md`; если не
     распознана — так и скажи;
   - `забыть <id>`/`forget <id>` — `routines forget <id>`: удали рутину по `id`
     или имени и подтверди результат;
   - `открыть <имя>`/`open <имя>` — найди рутину в
     `C:\Users\er-ka\Documents\z-code\ctxdb\routines\routines.json` по `id` или
     `name`, прочитай файл
     `C:\Users\er-ka\Documents\z-code\ctxdb\routines\<id>\SKILL.md` и покажи его
     содержимое.
2. Запускай только эти команды и пути. Ничего не устанавливай, не переписывай
   `routines.json` руками и не создавай скиллы вручную.
3. Если CLI упал, приведи текст ошибки и назови причину: демон не запущен,
   не найден каталог ctxdb, пустая база.
4. Числа не выдумывай: `uses` — это число похожих запросов, которые видел
   майнер, а не число применений скилла.

Аргумент пользователя: $ARGUMENTS
