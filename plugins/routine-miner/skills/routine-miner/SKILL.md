# routine-miner — скилы из типовых задач

Майнер ищет в истории повторяющиеся формулировки, собирает похожие в кластер и
пишет из кластера скилл: `SKILL.md` с сутью, прошлыми шагами и триггерами. Дальше
хук `UserPromptSubmit` сам находит рутину под новый промпт и подставляет
короткий блок `<routine>` — вместо повторного разбора с нуля.

## Как устроено

1. **Индекс.** ctxdb собирает запросы пользователя (`kind=chat_user`) по всем
   проектам: `%USERPROFILE%\.zcode\cli\db\db.sqlite`, `tasks-index.sqlite`,
   каталог памяти.
2. **Кластеризация.** Майнер берёт до 400 последних запросов, дедуплицирует по
   тексту и считает эмбеддинги `multilingual-e5-small` (384d, q8, CPU).
   Формулировки с косинусом **≥ 0.87** считаются одной; кластер от **2**
   запросов становится рутиной.
3. **Скилл.** Для кластера пишется `routines\<id>\SKILL.md`: суть, до трёх шагов
   «как это обычно делалось» (из ответов агента в тех же задачах), триггеры,
   правила применения. Рядом `samples.json` — исходные формулировки.
4. **Реестр.** `routines\routines.json` хранит `id`, `name`, `uses`, `triggers`,
   `status`, `projects`, `steps` и путь к скиллу. Реестр общий: рутины видны из
   любого проекта, поэтому опыт переносится между проектами.
5. **Векторный след.** Каждая рутина пишется чанком `kind=routine`, чтобы
   находиться обычным поиском ctxdb.
6. **Подстановка.** На `UserPromptSubmit` хук ищет лучшую рутину по покрытию
   слов с нечётким сравнением: точное совпадение, префикс для слов от 5
   символов, общий корень из 4 символов. Порог — **0.45**. Ниже порога блок не
   вставляется, вставка не тратит токенов.

## Токены

- Эмбеддинги и сравнение — локальные, **0 токенов**.
- Блок `<routine>` — навигация: имя, статус, `uses`, `score`, суть и абсолютный
  путь к `SKILL.md`. Сама навигация — ~40-60 токенов, вместе с длинным путём на
  этой машине выходит ~130 токенов.
- Полный чек-лист — один `SKILL.md` (~250-350 токенов) и только когда агент к
  нему обратился.
- Совпадения нет — вставки нет: 0 токенов.

## Что выполнять

CLI майнера:

```
node "C:\Users\er-ka\Documents\z-code\ctxdb\src\cli.mjs" routines <подкоманда>
```

| Задача | Команда |
|---|---|
| статус: рутины, повторы, топ | `routines status` |
| найти и обновить рутины | `routines scan` |
| проверить распознавание фразы | `routines test "<текст>"` |
| удалить рутину по `id` или имени | `routines forget <id>` |

Открыть скилл: `C:\Users\er-ka\Documents\z-code\ctxdb\routines\<id>\SKILL.md`.
Формат блока, который вставляет хук:

```
<routine name="github-plugin-github-zcode-plugins-offic" status="auto" uses="4" score="0.51">
Типовое задание — не разбирай с нуля. Суть: подключим аккаунт GitHub
Чек-лист и подробности: открой файл скилла "...\routines\ba450cee50\SKILL.md" и следуй ему.
Ты уже делал это 4 раз. Скилл сгенерирован автоматически, при расхождении с реальностью — уточни у пользователя.
</routine>
```

## Когда рутина не подошла

- Блок помечен `status="auto"`: скилл собран автоматически. Если шаги расходятся
  с реальностью — скажи об этом пользователю, не подгоняй факты.
- Открывай `SKILL.md` только когда задача действительно повторная.
- `uses` — сколько похожих запросов видел майнер, а не сколько раз скилл
  применяли.
- Мало истории — мало рутин: кластеру нужно минимум два запроса.
- `forget` удаляет запись и её вектор, но не трогает историю чатов.

## Ограничения

- Windows-only: пути, CLI и хуки рассчитаны на эту установку.
- Стемминг наивный: общий корень в 4 символа, поэтому короткие и редкие слова
  иногда дают ложные совпадения. Порог 0.45 отсекает большую часть шума, но не
  всю.
- Шаги собираются из коротких ответов агента, а не из полного лога; деталей
  может не хватить — тогда в скилле стоит заглушка, а не выдуманный шаг.
- Майнер не заменяет ручные скиллы: сложные процедуры с проверками лучше писать
  руками.
- Автопрогон — при старте демона и не чаще раза в сутки.
- После правок кода майнера нужен `daemon stop` и `daemon start`.
